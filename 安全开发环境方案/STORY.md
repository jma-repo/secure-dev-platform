# STORY.md — 安全开发环境与权限化 RAG

## ① 意图对齐

这份 PPT 用在客户需求尚未定稿的方案沟通会上，听众是同一家公司里的两类人：懂技术的 IT/开发负责人，和不懂技术但管预算、管风险的管理层。讲完之后希望他们相信三件事：RAG 不是训练模型；"数据不出内网"和"用云端 Copilot"是互斥的两个选择；安全不是买扫描器，而是把检查放在每条必经之路上。并希望他们当场做出五个决定（数据能否出网、有没有 M365 许可、身份源用哪个、环境分几套、RPO/RTO 与预算形态）。全篇 15 页，其中 hero 页 3 页（封面、五道关卡、结束页），视觉调性锁定为"克制、可审计、工程感、不炫技"，用低饱和墨绿 + 一处砖红强调，配等宽字体承载数字与文件名。内容边界：必讲需求澄清、三条路线取舍、离线可行性与代价、容灾、已验证/待验证的诚实边界；不讲具体报价、不讲未落地的云上架构细节、不碰"我们已经全部做完"这类表述。

## ② 页面骨架

全篇 15 页，分 3 章，目录声明 3 章 → 全篇有且仅有 3 个 `type: section` 章节扉页，编号 01/02/03 连续，标题与目录逐字一致：
- 第 01 章「需求对齐」→ 扉页 P03，覆盖 P03–P05
- 第 02 章「方案与安全设计」→ 扉页 P06，覆盖 P06–P11
- 第 03 章「现状与下一步」→ 扉页 P12，覆盖 P12–P14

Hero 页 3 页（P01 封面、P09 五道关卡、P15 结束页），占比 20%，两两之间均间隔 ≥1 个 supporting 页。rhythm：P01 peak → P02 valley → P03 transition → P04/P05 valley → P06 transition → P07/P08 valley → P09 peak → P10/P11 valley → P12 transition → P13/P14 valley → P15 peak。非对称版式共 7 页（P04/P05/P08/P09/P10/P11/P14，占 47% ≥ 40%）；对称版式仅用于 P07、P13（图表+洞察）与 P03/P06/P12（章节扉页）及 P02 目录。
